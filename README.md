# Mul-Mat Project

## 프로젝트 소개

이 프로젝트는 Next.js 15를 기반으로 한 웹 애플리케이션입니다. Feature-Sliced Design 아키텍처를 적용하여 확장 가능하고 유지보수가 용이한 구조로 설계되었습니다.

커피의 98%는 물로 이루어져 있으며, 이는 커피의 맛에 결정적인 영향을 미칩니다. 바리스타로 일하며 여러 매장에서 변화하는 수질로 인해 커피의 일관성을 유지하기 어려워하는 상황을 목격했습니다. 이를 해결하기 위해 공공데이터 기반 지역별 취정수장의 월별 수질 정보를 제공하는 서비스를 만들었습니다. 결과적으로 타겟층이 명확한 카테고리 킬링 서비스를 구현했습니다.

🌐 **서비스 도메인**: [http://mulmat-app.site/](http://mulmat-app.site/)

## 기술 스택

### Frontend

- **Framework**: Next.js 15.2.2
- **Language**: TypeScript
- **UI Library**: React 19
- **State Management**:
    - Zustand (클라이언트 상태 관리)
    - TanStack Query (서버 상태 관리)

### Development Tools

- **Styling**: TailwindCSS
- **PWA Support**: next-pwa

- PWA (Progressive Web App) 지원
- 모바일 최적화 디자인 시스템
- 서버 사이드 렌더링 (Next.js)
- 공공데이터 기반 지역별 취정수장 수질 정보 제공
- 커피 추출에 최적화된 물 정보 분석

## 프로젝트 구조 (FSD 아키텍처)

```
mul-mat/
├── app/          # nextjs 페이지 라우팅, api 라우트
├── src/
│ ├── shared/     # 공통 유틸리티, UI 키트, API
│ ├── entities/   # 비즈니스 엔티티 (사용자, 상품 등)
│ ├── features/   # 비즈니스 기능 구현
│ ├── widgets/    # 복합 UI 컴포넌트
│ └── views/      # 페이지 컴포넌트
├── public/       # 정적 파일
├── public/ # 정적 파일
└── ...
```

### FSD 레이어 설명

- app : 최상위 컴포넌트, 프로바이더 설정 등
- shared : 공통으로 사용되는 UI 컴포넌트, 유틸리티 함수, API 클라이언트
- entities : 핵심 비즈니스 엔티티 모델 및 관련 로직
- features : 사용자 시나리오 및 비즈니스 기능 구현
- widgets : 여러 features를 조합한 복합 UI 블록
- views : 최종 스크린 컴포넌트

## 데이터 페칭 최적화 (BFF 및 캐싱 전략)

본 프로젝트는 외부 데이터 의존성으로 인한 불확실성을 관리하고 높은 성능을 유지하기 위해
BFF(Backend for Frontend) 아키텍처와 Next.js의 캐싱 전략을 도입.

### 배경 및 목적

주요 데이터 소스인 공공 데이터 API는 업데이트 주기가 명확하지 않아,
사용자가 항상 최신 데이터를 보고 있는지 보장하기 어렵습니다.
이러한 불확실성을 클라이언트에서 직접 처리하게 되면 로직이 복잡해지고,
불필요한 API 요청을 유발하여 서비스 안정성을 저해할 수 있습니다.
이를 해결하기 위해 **BFF가 데이터 요청을 전담**하여 클라이언트의 부담을 낮추고,
**Next.js의 캐싱 기능으로 반복적인 외부 API 호출을 방지**하여 트래픽 증가에 효과적으로 대응하는 것을 목표로 삼았습니다.

### 데이터 처리 흐름

**단일 API 요청**: 클라이언트는 useRouter를 통해 서버의 BFF 엔드포인트로 매개변수 없이 요청합니다.
**최신 데이터의 날짜 전용 훅**: nextjs 캐싱, 불필요한 매개변수 전달이나, 불필요한 로직을 제거해 기존 로직 대비 90%+ 빠른 데이터 페칭이 가능해졌고,
데이터가 없을 시에 파라미터인 month - 1 하는 구조로 공공 데이터 서버의 최신 날짜를 받으면 반환하게 됩니다.

### 도입 효과

**클라이언트 복잡성 대폭 감소**: 데이터 업데이트의 불확실성과 최신 데이터 추적의 부담을 BFF가 모두 흡수합니다.
클라이언트는 복잡한 상황을 고려할 필요 없이, 원하는 시점의 데이터만 요청하면 되어 로직이 매우 단순해집니다.
**성능 및 비용 효율성 (Next.js 캐싱)**: Next.js의 fetch 캐싱을 통해 한 번 조회된 공공 데이터는 일정 시간 동안 재사용됩니다.
덕분에 **사용자가 급증하더라도 불필요한 외부 API 호출을 최소화**하여 비용을 절감하고, 빠르고 안정적인 응답 속도를 보장합니다.

**유지보수성 및 확장성**: 데이터 소스 연동 및 가공 로직이 모두 BFF에 중앙화되어 있어,
향후 데이터 소스가 변경되거나 비즈니스 로직이 추가되어도 클라이언트 코드 수정 없이 서버만 대응하면 되므로 유지보수가 용이합니다.
